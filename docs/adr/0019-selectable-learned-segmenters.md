# Selectable segmenters: the learned student and teacher ship beside v6, each draft records which one made it

Two learned segmenters cleared the rally-level gate v2 (#100) on held-out, hand-verified recordings, far ahead of v6 on the thing the product needs most — not inventing rallies: span precision 0.99 for both (1.7 invented rallies/h) against v6's 0.76 (56/h), recall on rallies ≥ 3 s 0.96–0.97 (v6 0.99), edges within 1 s 82–87 % (v6 32 %). They ship as **choices**, not a silent replacement (#105):

- **Student** — gradient-boosted trees on the three signals v6 already computes (motion energy, audio level + hit onsets, YOLOX person boxes at 3 fps). It costs what v6 costs, runs anywhere, and is the **default**.
- **Teacher** — TrackNetV3 shuttle track (non-overlapping mode, 8× cheaper than the offline run and still green) plus RTMPose-t player pose over the whole recording, fed to a logistic-regression context model and a learned edge refiner. The most accurate; it wants a GPU and the UI says so.
- **v6** — the heuristic stays selectable. It keeps the highest recall on very short rallies, and it is what every existing timeline was drawn with.

The choice is **per library**, stored in the per-device `meta` table, because a shared library's members each choose for themselves and a laptop without a GPU should not be forced onto the teacher by a desktop.

**Identity is a segmenter id plus that segmenter's own version.** `SEGMENTER_VERSION` alone meant both *which* segmenter and *how new*; adoption took the highest number and the stale path re-derived anything lower — right for one lineage, wrong for parallel ones (a student draft is not "newer" than a v6 draft, nor older). Each recording now stores `segmenter_id` beside `segmenter_version` (a NULL id is the legacy `v6`). An Analysis file (ADR 0013) carries the id too and is named per segmenter — v6 keeps its existing `_s{N}` names so older builds still find their files; the learned segmenters publish as `_{id}{N}`. Adoption takes only Analyses from the library's chosen segmenter, the highest version within it.

**Switching re-derives untouched drafts only.** The stale-resegment path (`resegment_stale_untouched`) now compares each ready recording's (id, version) with the library's chosen segmenter, not with a global number; a recording a human has touched (a flag, a hand-corrected rally, an annotation) is never re-derived, exactly as with version bumps today. Explicit Re-analyze keeps its documented meaning (discards corrections, ADR 0002).

**Rally edges are strict** — serve contact to the shuttle touching the floor or failing at the net — because that is what the models were trained and judged on. Padding is a playback/export concern (#104), not baked into stored rallies as v6's 1.2 s pad is.

**The models are files with a contract, and the app's code is a port of the training code.** The student's model (`models/student-v1.json`) carries its feature layout and is refused if the app computes a different one; numpy's arithmetic is mirrored where it decides an outcome. Parity is checked on the whole corpus: the in-app timeline must match the offline one (stated tolerance in #105). A retrained model is a new version of its segmenter and goes through gate v2 again before it ships.

Rejected: **replacing v6 outright** — the learned segmenters miss more very short rallies and every existing draft is v6's, so users keep a path back; **a global (per-device) choice** — a device that holds both a local and a shared library may reasonably want the fast segmenter for one and the accurate one for the other; **encoding the segmenter in the version number** (e.g. student = 1000+N) — it keeps one integer but turns "newer" into "different", and adoption's highest-wins rule would silently prefer whichever family had the bigger numbers; **re-deriving hand-touched drafts on switch** — it would destroy review work to apply a preference.
